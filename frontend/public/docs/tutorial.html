本文用于指导用户把 121API 中转站接入 CC Switch，并在 Codex 中使用。教程按照真实后台流程整理，图片均为 121API 自有操作截图。

配置项请以 121API 后台和 CC Switch 导入窗口显示为准，尤其是 API 端点、API 密钥和模型名称，不要凭经验手动改。

1一、适合谁看

适合以下用户：

1. 已经有 121API 中转站账号
2. 想把 121API 接入 Codex
3. 想用 CC Switch 统一管理 Codex 供应商配置
4. 想让本地 Codex 使用 121API 的模型服务

不需要手动编辑复杂配置文件，按本文流程走即可。

3三、下载并安装 CC Switch

CC Switch 用来接收 121API 的一键导入配置，并写入 Codex 供应商信息。

官方下载地址：CC Switch Releases

国内备用下载：

Windows 电脑：下载 .msi 安装包

苹果电脑：下载 .dmg 安装包

下载完成后打开安装包，按提示安装并启动 CC Switch。后面在 121API 点击 导入到 CCS 时会自动拉起它。

4四、注册 121API 账号

打开 121API 注册页，填写邮箱、密码和优惠码，点击 继续。

注册完成后登录后台，进入控制台。

5五、进入 API 密钥页面

在后台左侧菜单点击 API 密钥。

页面右上角和空状态区域都可以创建密钥，点击任意一个 创建密钥 按钮即可。

6六、创建 API 密钥

在弹窗中填写密钥名称。建议单独给 Codex 创建一个专用密钥，例如：

codex5.5

然后选择要使用的分组，点击 创建。

创建成功后，密钥会出现在列表中。

确认这些信息正常：

密钥名称
API 密钥
分组
状态
创建时间
操作区

安全提醒：API Key 等同于调用权限，不要公开发布真实密钥，不要写进公开仓库。

7七、导入到 CC Switch

在密钥列表右侧操作区点击 导入到 CCS。

浏览器会弹出确认窗口，点击 打开 CC Switch。

CC Switch 打开后会进入供应商导入确认页。重点核对以下字段：

应用类型：Codex
供应商名称：121API 中转站
官网地址：https://121api.com
API 端点：以导入窗口显示为准
API 密钥：确认已自动带入
模型：以导入窗口显示为准

确认无误后点击 导入。

8八、检查 Codex 供应商配置

导入后进入 CC Switch 的供应商编辑页，先检查基础配置。

重点看：

供应商名称
官网链接
API Key
API 请求地址
模型名称

如果这些字段已经自动填好，一般不需要手动修改。

继续向下检查 Codex 配置内容。

重点确认：

auth.json 中已经写入 OPENAI_API_KEY
config.toml 中 model_provider 指向 121api
base_url 与导入的 API 端点一致
model 与导入窗口显示的模型一致

确认无误后点击 保存。

9九、启用供应商

回到供应商列表，找到 121API 中转站，点击右侧 启用。

启用后，Codex 会优先使用这套 121API 中转站配置。

11十一、第一次使用建议

第一次使用时，不建议直接让 Codex 修改代码。先让它阅读项目，确认它理解项目结构后再开始开发。

推荐提示词：

请先不要修改代码。
请阅读当前项目，并输出：
1. 项目技术栈
2. 主要目录结构
3. 启动方式
4. 核心模块位置
5. 后续开发建议

需要开发功能时，可以这样说：

我要增加一个 XXX 功能。
请先分析需要修改哪些文件，不要直接改。
等我确认方案后再开始修改。

推荐开发流程：

先读项目
再分析方案
确认后修改
查看 diff
运行测试
人工确认后合并

12十二、常见问题

1. 点击导入到 CCS 没反应

先确认 CC Switch 已经安装，并且能正常打开。

如果浏览器提示是否打开外部应用，要选择允许。

2. 导入后 Codex 没生效

检查 121API 中转站 供应商是否已经启用。

然后完全退出 Codex，再重新打开。

如果仍然不生效，重新打开终端或重启 Codex 客户端后再试。

3. API 端点应该填什么

优先使用 121API 导入到 CC Switch 时自动生成的 API 端点。

不要手动改成其它路径。

4. 模型名称应该填什么

以 121API 后台或 CC Switch 导入窗口显示为准。

窗口显示什么，配置里就用什么。

5. 可以直接让 Codex 改生产项目吗

不建议。实际开发时至少做到：

1. 使用 Git
2. 新建分支
3. 先分析方案
4. 小范围修改
5. 查看 diff
6. 测试通过后再合并

13十三、最终总结

这套接入的核心是：

121API 提供 API 密钥和模型接口
CC Switch 负责写入 Codex 配置
Codex 负责实际项目开发

跑通一次后，后续切换模型、更换密钥、停用供应商，都优先在 CC Switch 中管理。
